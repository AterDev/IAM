# Stage2：前端功能增强开发任务

## 目标

本阶段聚焦 `IAM功能清单` 中“推荐补充清单”的前端部分，目标是在 Stage1 解决核心认证闭环之后，把前端从“管理后台 + 基础认证页面”增强为“更完整的身份平台交互层”。

本文档面向后续编码型 LLM 或工程师，要求：

- 优先复用现有 Angular 管理端架构
- 新能力必须围绕真实后端场景设计，不做假交互
- 页面增强要兼顾平台化、治理化、运营化与可扩展性
- 所有高风险功能都要保留错误反馈、状态展示与权限感知

## 范围边界

本阶段前端优先处理以下事项：

1. Passkey / WebAuthn 页面与交互
2. 风险控制与挑战式交互页面
3. 开发者门户与动态客户端注册页面
4. 组织同步 / 外部目录同步可视化页面
5. 多租户前端适配能力
6. 高级 OAuth 能力配置界面
7. 审计报表与导出页面
8. 运营监控与安全告警页面
9. Claims 映射与身份资料治理页面
10. Password Grant 收敛提示与迁移辅助页面

## 任务执行方式

Stage2 前端任务更偏“平台产品化界面增强”，建议每个任务都按以下维度理解：

- **先后依赖**：先依赖哪个后端能力，再安排页面落地
- **建议拆分**：一轮一轮交给 LLM 时的合理粒度
- **预计改动文件**：优先锁定页面、服务、路由、共享组件
- **测试点**：至少可手动回归验证的关键路径

## 任务 1：Passkey / WebAuthn 页面与交互

- 目标：

为用户提供可操作的 Passkey / WebAuthn 注册、验证、管理体验。

- 重点页面：

- 用户安全设置页
- 登录页
- 设备管理页（如新增）

- 实现要点：

- 提供注册 Passkey 的向导式页面
- 提供 Passkey 登录入口
- 展示已绑定设备/凭证列表
- 支持删除或停用某个凭证
- 对浏览器不支持 WebAuthn 的情况给出明确提示

- 注意事项：

- WebAuthn 前端调用必须严格按浏览器 API 要求处理二进制数据
- 需要清晰区分“浏览器不支持”“用户取消”“验证失败”“后端拒绝”几类错误
- 页面文案要适合非技术用户理解

- 先后依赖：

- 依赖后端 Stage2 任务 1
- 建议在 Stage1 MFA 页面稳定后再接入

- 建议拆分：

1. 安全设置页增加 Passkey 入口
2. 登录页增加 Passkey 登录入口
3. 增加凭证管理页面

- 预计改动文件：

- `src/ClientApp/WebApp/src/app/pages/**`
- `src/ClientApp/WebApp/src/app/services/**`
- 路由与共享组件目录

- 测试点：

- 浏览器支持场景下可注册并登录
- 不支持 WebAuthn 时有明确提示
- 删除凭证后不可继续使用该凭证

## 任务 2：风险控制与挑战式交互页面

- 目标：

为后端风控能力提供可落地的前端交互承接，而不是把所有风控失败都显示成普通报错。

- 实现要点：

- 支持验证码、人机校验、额外验证步骤的页面承接
- 对高风险登录给出二次验证 UI
- 对限流、锁定、异常访问给出明确状态页或弹窗提示
- 对设备流轮询限制、异常授权请求等场景提供更可理解反馈

- 注意事项：

- 风控挑战页面不能写死为某一家验证码服务
- 应设计抽象的 challenge 渲染层，便于后续切换实现
- 要区分安全拦截、业务失败、系统异常三类文案

- 先后依赖：

- 依赖后端 Stage2 任务 2
- 与 Stage1 登录页、授权页、设备页可复用一部分错误处理组件

- 建议拆分：

1. 抽象 challenge 承接层
2. 登录风控挑战 UI
3. 授权 / 设备流异常提示增强

- 预计改动文件：

- `src/ClientApp/WebApp/src/app/pages/login/*`
- `src/ClientApp/WebApp/src/app/pages/authorize/*`
- `src/ClientApp/WebApp/src/app/pages/device-code/*`
- 共享弹窗或 challenge 组件

- 测试点：

- 触发挑战时页面正确跳转或弹出
- 限流、锁定、挑战失败提示清晰
- 解除挑战后流程可继续

## 任务 3：开发者门户与动态客户端注册页面

- 目标：

为接入方提供客户端申请、查看、维护的自助门户体验。

- 重点页面：

- 客户端申请页
- 客户端详情页
- Secret 管理页
- 回调地址与权限配置页

- 实现要点：

- 支持创建不同类型客户端
- 支持配置 redirect URI、logout URI、scope、resource
- 支持 secret 一次性展示与轮换提示
- 支持审核中、启用中、已禁用等状态展示
- 支持开发者查看接入文档、示例配置与错误说明

- 注意事项：

- Secret 明文不能反复展示
- 要显式区分 Public client 和 Confidential client 能填写的字段
- 表单校验要覆盖 URI 格式、重复项、非法 scope 选择等问题

- 先后依赖：

- 依赖后端 Stage2 任务 3
- 与现有客户端管理页强相关，建议在其基础上增量增强

- 建议拆分：

1. 开发者门户入口与列表页
2. 客户端申请 / 编辑表单
3. secret 管理与状态页

- 预计改动文件：

- `src/ClientApp/WebApp/src/app/pages/client/**`
- 可新增 `developer-portal` 目录
- `src/ClientApp/WebApp/src/app/services/api/**`

- 测试点：

- 新客户端可提交申请
- Secret 可一次性展示与轮换
- 不同客户端类型表单字段正确切换

## 任务 4：组织同步 / 外部目录同步可视化页面

- 目标：

让管理员能看到外部目录或 SCIM 同步结果，而不是只能从日志排查。

- 实现要点：

- 展示最近同步任务状态
- 展示成功、失败、冲突数量
- 展示用户/组织变更明细
- 提供重试、查看错误、筛选同步源等能力
- 提供冲突处理或人工确认入口（如后端支持）

- 注意事项：

- 不要把同步页面做成纯日志堆砌
- 要突出“问题定位效率”，例如显示冲突原因和对象定位链接
- 对大规模同步结果注意分页与性能

- 先后依赖：

- 依赖后端 Stage2 任务 4
- 与多租户页面有一定交叉，但可先做只读同步中心

- 建议拆分：

1. 同步任务列表页
2. 同步详情与冲突页
3. 重试与错误定位交互

- 预计改动文件：

- 可新增 `sync` / `directory-sync` 页面目录
- `src/ClientApp/WebApp/src/app/services/api/**`
- 公共表格与详情组件

- 测试点：

- 同步任务状态展示正确
- 冲突详情可查看与定位
- 大量同步结果分页不崩溃

## 任务 5：多租户前端适配能力

- 目标：

为未来多租户模型提供前端可视化与上下文切换能力。

- 实现要点：

- 增加租户选择器或租户上下文显示
- 区分平台管理员与租户管理员视图
- 在列表、详情、配置页中体现租户边界
- 为租户专属配置与平台共享配置提供不同展示方式

- 注意事项：

- 前端不能只显示租户名称，仍需以后端返回的租户上下文为准
- 要避免租户切换后页面残留旧数据
- 需要统一处理租户无权限访问时的反馈

- 先后依赖：

- 依赖后端 Stage2 任务 5
- 建议在路由守卫、全局状态、布局层统一考虑

- 建议拆分：

1. 租户上下文显示与切换入口
2. 页面按租户展示数据
3. 平台管理员 / 租户管理员视图分流

- 预计改动文件：

- `src/ClientApp/WebApp/src/app/layout/**`
- 路由守卫、全局状态服务
- 各列表/详情页公共数据加载逻辑

- 测试点：

- 切换租户后页面数据同步刷新
- 无权限租户访问被拦截
- 平台级与租户级页面边界清晰

## 任务 6：高级 OAuth 能力配置界面

- 目标：

为未来的 PAR、DPoP、Token Exchange、JAR/JARM 等高级能力提供管理端配置入口。

- 实现要点：

- 在客户端配置页中增加高级安全能力开关区
- 为不同客户端类型动态显示适用选项

- 支持能力启用前的校验与预检查结果展示

- 注意事项：

- 不要一次把所有高级配置都暴露成复杂表单
- 建议先按“实验性 / 受限 / 正式支持”分级展示
- 高级能力配置必须有帮助文本，否则 LLM 和人工都容易误用

- 先后依赖：

- 依赖后端 Stage2 任务 6
- 与客户端配置页、Claims 配置页有关联

- 建议拆分：

1. 客户端页增加高级能力配置区域
2. 增加说明、依赖校验、风险提示
3. 增加启用前检查结果展示

- 预计改动文件：

- `src/ClientApp/WebApp/src/app/pages/client/**`
- 公共配置表单组件
- `src/ClientApp/WebApp/src/app/services/api/**`

- 测试点：

- 不同客户端类型展示不同配置项
- 未满足条件时给出明确提示
- 启用高级能力不影响普通配置流程

## 任务 7：审计报表与导出页面

- 目标：

将现有审计中心增强为“可分析、可导出、可服务运营与合规”的前端模块。

- 实现要点：

- 提供登录趋势、失败事件、授权记录、风险事件等报表页

- 提供导出任务创建、进度查询、下载入口
- 提供筛选器与预置时间范围

- 注意事项：

- 图表组件不要与业务数据结构强耦合
- 大数据量导出必须采用异步任务方式展示，不要阻塞 UI
- 导出按钮要结合权限控制与敏感数据提示

- 先后依赖：

- 依赖后端 Stage2 任务 7
- 可与运营监控页面并行推进

- 建议拆分：

1. 报表筛选与图表页
2. 导出任务列表与详情页
3. 下载入口与状态提示

- 预计改动文件：

- `src/ClientApp/WebApp/src/app/pages/security/**`
- 可新增 `reports` / `export-tasks` 页面目录
- 图表与表格共享组件

- 测试点：

- 筛选条件可正确刷新图表和列表
- 导出任务创建后能查看进度与下载
- 无权限用户不能导出敏感数据

## 任务 8：运营监控与安全告警页面

- 目标：

让平台管理员可以直接从前端看到关键健康状态与安全告警。

- 实现要点：

- 展示签名密钥即将过期状态
- 展示客户端 secret 过期提醒
- 展示异常登录峰值、失败率、限流事件等指标
- 展示告警列表、告警级别、已处理状态
- 为告警详情提供关联对象跳转能力

- 注意事项：

- 监控页不应只堆指标，要能辅助定位问题
- 告警信息需要区分实时态和历史态
- 前端轮询频率要控制，避免监控页本身成为压力源

- 先后依赖：

- 依赖后端 Stage2 任务 8
- 与报表页面可共享部分可视化组件

- 建议拆分：

1. 健康与关键指标总览页
2. 告警列表与详情页
3. 已处理状态与关联跳转

- 预计改动文件：

- 可新增 `operations` / `alerts` 页面目录
- 图表、指标卡片、告警列表组件
- `src/ClientApp/WebApp/src/app/services/api/**`

- 测试点：

- 指标总览页正确展示关键状态
- 告警详情可跳转到关联对象
- 已处理状态切换后 UI 同步更新

## 任务 9：Claims 映射与身份资料治理页面

- 目标：

让管理员可配置 claims 映射、字段下发策略和身份资料展示规则。

- 实现要点：

- 提供标准 claim 与自定义 claim 的映射配置页
- 支持按 client / scope / resource 查看下发策略
- 支持敏感字段标记与脱敏说明
- 提供预览某个客户端在给定 scope 下的 claims 输出结果

- 注意事项：

- 页面设计要突出“谁会收到什么数据”，避免配置歧义
- 需要可视化说明 Token、UserInfo、Profile 三类输出差异
- 复杂映射规则建议支持只读预览和变更确认

- 先后依赖：

- 依赖后端 Stage2 任务 9
- 与客户端配置页、高级 OAuth 配置页有联动

- 建议拆分：

1. claims 映射列表与编辑页
2. scope / client / resource 视角切换
3. 输出预览与变更确认

- 预计改动文件：

- 可新增 `claims-governance` 页面目录
- `src/ClientApp/WebApp/src/app/services/api/**`
- 配置表单与预览组件

- 测试点：

- 映射配置保存后可正确回显
- 预览结果能反映 client / scope 差异
- 敏感字段配置有明确提示

## 任务 10：Password Grant 收敛提示与迁移辅助页面

- 目标：

帮助管理员逐步识别和收敛 Password Grant 的使用，而不是只在后端静默限制。

- 实现要点：

- 在客户端详情页标记是否仍启用 Password Grant
- 提示风险等级与推荐替代方案
- 展示最近仍在使用 Password Grant 的客户端与调用趋势
- 为迁移提供指引，例如建议改用授权码 + PKCE、设备码等

- 注意事项：

- 页面文案要明确传达“弃用计划”，但不能吓到仍需迁移的接入方
- 收敛提示应结合真实调用数据，而不是静态说明
- 要避免在 UI 上误导管理员以为“一键关闭”不会影响现网系统

- 先后依赖：

- 依赖后端 Stage2 任务 10
- 与报表、客户端详情页可共享调用趋势与风险数据

- 建议拆分：

1. 在客户端详情页增加风险提示
2. 增加 Password Grant 使用概览页
3. 增加迁移建议与操作引导

- 预计改动文件：

- `src/ClientApp/WebApp/src/app/pages/client/**`
- 可新增 `grant-migration` 页面目录
- `src/ClientApp/WebApp/src/app/services/api/**`

- 测试点：

- 启用 Password Grant 的客户端会被正确标记
- 风险提示与真实后端数据一致
- 迁移建议页能按客户端展示替代方案

## 页面与模块优先级建议

建议按以下顺序推进前端增强：

1. 审计报表与运营监控
2. 开发者门户与客户端自助管理
3. Claims 治理与高级 OAuth 配置页
4. 风控挑战页面
5. Passkey / WebAuthn 页面
6. 多租户与同步可视化页面
7. Password Grant 收敛与迁移辅助页

## 交付要求

本阶段前端完成后，应至少满足：

- 后台从“管理 CRUD”升级到“具备平台治理视角”
- 所有增强页面都能承接真实后端状态，不使用伪数据描述核心流程
- 高风险功能都有明确说明、错误反馈与权限感知
- 文档结构足够清晰，便于后续 LLM 继续迭代编码

## 测试建议

- Passkey 注册 / 登录 / 删除凭证
- 风控挑战触发 / 解除 / 限流提示
- 动态客户端注册 / Secret 轮换 / 审核状态切换
- 同步任务成功 / 失败 / 冲突展示
- 多租户切换与权限变化
- 审计报表筛选与导出任务查询
- 告警列表、详情、已处理状态
- Claims 映射预览与配置变更
- Password Grant 风险提示与迁移提示
