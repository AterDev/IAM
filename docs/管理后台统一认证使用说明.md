# 管理后台统一认证使用说明

## 目的

管理后台 `src/ClientApp/WebApp` 现已默认复用本项目自身的 IAM / OAuth 2.0 / OIDC 能力，不再把自定义 `api/admin/login` 作为主登录入口。

当前采用的主链路是：

- **授权码模式（Authorization Code）**
- **PKCE**
- **统一会话标识 `sid`**
- **统一注销 `/connect/logout`**

这样做的目标是让：

- 管理后台与认证中心共享同一套身份体系
- 登录、授权、刷新、会话、注销语义保持一致
- 后续 MFA、外部登录、统一会话传播都能沿同一链路继续扩展

## 默认数据

本地开发环境下，**无需手工新增额外默认数据** 即可使用管理后台统一认证。

现有种子数据已经包含：

- 默认管理员账号
  - 用户名：`admin`
  - 密码：`Perigon.2026`
- 默认管理后台客户端：`AdminWebClient`
  - 回调地址：`http://localhost:4200`、`https://localhost:4200`
  - OIDC callback：`http://localhost:4200/auth/callback`、`https://localhost:4200/auth/callback`
  - 登出回调地址：`http://localhost:4200`、`https://localhost:4200`
- 默认示例前端客户端：`FrontSampleClient`
  - 回调地址：`http://localhost:4201`、`https://localhost:4201`
  - 登出回调地址：`http://localhost:4201`、`https://localhost:4201`
- 默认作用域：`openid profile email offline_access`

如果数据库来自较早版本，启动时会自动补齐缺失的 `AdminWebClient`、`FrontSampleClient` 与对应回调地址。

## 当前登录方式

### 管理后台主登录入口

1. 打开 `http://localhost:4200`
2. 点击“前往统一登录”
3. 浏览器跳转到 IAM 服务的 `/connect/authorize`
4. 如尚未登录，会继续跳转到后端 Razor 登录页 `/Account/Login`
5. 登录成功后，如需要授权确认，会显示 `/Account/Consent`
6. 授权完成后自动回到管理后台

### 会话与令牌说明

- 管理后台前端通过自身实现的授权码 + PKCE 流程获取访问令牌与刷新令牌
- 服务端会在 Cookie、访问令牌、刷新令牌与 `LoginSession` 记录之间统一维护 `sid`
- 管理后台收到的访问令牌已包含后台接口所需的管理员角色 claim 与统一会话标识

## 注销方式

管理后台退出会调用统一 OIDC 登出链路：

- 前端清理本地认证状态
- 调用 `/connect/logout`
- 服务端按当前 `sid` 撤销会话
- 后续使用旧访问令牌访问后台接口将返回 `401`

## 兼容说明

为避免一次性切断所有旧链路，当前仍保留：

- `POST /api/admin/login`

但它现在只作为**兼容入口**保留，不再是管理后台 WebApp 的默认登录方式。

后续若要完全移除旧入口，建议在以下条件都满足后再做：

1. 管理后台统一 OIDC 登录已稳定运行
2. 自动刷新与统一注销已经通过回归验证
3. 旧集成方已完成迁移

## 本地验证建议

### 验证 1：统一登录

1. 启动 AppHost
2. 访问 `http://localhost:4200`
3. 点击“前往统一登录”
4. 使用 `admin / Perigon.2026` 登录
5. 确认最终回到管理后台并可访问用户、角色、会话页面

### 验证 2：统一会话

1. 登录后打开“会话管理”
2. 确认存在当前登录会话
3. 记录当前 `sessionId`

### 验证 3：统一注销

1. 在管理后台点击登出
2. 确认浏览器返回 `/login`
3. 使用登出前的访问令牌再次调用后台接口，应返回 `401`

### 验证 4：客户端拆分

1. 访问管理后台登录入口时，应由 `AdminWebClient` 发起 `/connect/authorize`
2. 访问示例前端登录入口时，应由 `FrontSampleClient` 发起 `/connect/authorize`
3. 两者应分别展示各自客户端名称与说明，而不是复用同一个前端客户端

## 启动排障

如果本地首次启动后出现以下现象：

- `/connect/authorize` 返回 `invalid_client`
- `https://localhost:7070` 长时间超时
- 数据库中 `Users`、`Roles`、`Clients`、`ApiScopes`、`ApiResources` 仍为空

通常说明 `ApiService` 先于 `IAM_dev` 数据库创建完成而启动，导致 `InitHostService` 初始化提前失败。此时请按以下顺序处理：

1. 保持 `MigrationService` 完成数据库与表结构初始化
2. 重新启动 `ApiService` 资源，让 `InitHostService` 重新执行种子逻辑
3. 确认数据库中已经存在默认管理员、`AdminWebClient`、`FrontSampleClient`、默认作用域与 `SampleAPI`
4. 再重新验证管理后台与示例前端登录流程

这类问题属于本地编排启动顺序问题，不表示客户端拆分或 IAM 内部角色授权模型本身配置错误。

## 当前边界

- MFA 登录中间态
- 外部身份源登录后的统一回流
- 自定义授权确认页与设备码页的完整真实交互
- 更细粒度的后台权限感知与 step-up authentication
