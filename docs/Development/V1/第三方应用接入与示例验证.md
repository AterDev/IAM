# 第三方客户端接入说明

## 🎯 适用范围

本文档仅说明第三方客户端如何接入 IAM，包括：

- 第三方 **SPA / Web 前端** 如何接入 IAM
- 第三方 **受保护 API** 如何接入 IAM 的 JWT / OAuth 验证

## 接入前准备

在第三方客户端接入前，需要先明确以下信息：

| 项目 | 说明 |
|---|---|
| IAM 地址 | 例如 `https://iam.example.com` |
| 客户端标识 | 第三方应用在 IAM 中登记的 `ClientId` |
| 回调地址 | 登录完成后 IAM 回跳的地址 |
| 登出回调地址 | 退出登录后的返回地址 |
| 作用域 | 例如 `openid profile email` |
| API 资源 | 如需访问受保护 API，需要明确对应 Resource |

---

## 第三方前端客户端接入

### 1. 在 IAM 中注册客户端

对于浏览器前端或 SPA，建议在 IAM 中创建一个客户端，并至少配置以下内容：

| 配置项 | 建议值 |
|---|---|
| `ClientId` | 第三方应用唯一标识，例如 `MySpaClient` |
| `Type` | `Public` |
| `ApplicationType` | `Spa` |
| `RequirePkce` | `true` |
| `ConsentType` | `Explicit` 或根据业务场景设置 |
| `RedirectUris` | 登录回调地址，例如 `https://app.example.com/auth/callback` |
| `PostLogoutRedirectUris` | 登出回调地址，例如 `https://app.example.com` |
| `Scopes` | 至少包含 `openid profile email` |
| `Resources` | 如需访问受保护 API，则加入对应 API 资源 |

### 2. 前端客户端需要的关键参数

第三方前端通常按 OIDC 授权码模式接入，并使用 PKCE。常见参数如下：

| 参数 | 说明 | 示例 |
|---|---|---|
| `authority` | IAM 地址 | `https://iam.example.com` |
| `client_id` | 在 IAM 中登记的客户端 ID | `MySpaClient` |
| `redirect_uri` | 登录回调地址 | `https://app.example.com/auth/callback` |
| `post_logout_redirect_uri` | 登出回调地址 | `https://app.example.com` |
| `response_type` | 建议固定为 `code` | `code` |
| `scope` | 请求作用域 | `openid profile email offline_access MyApi` |
| `code_challenge_method` | PKCE 方法 | `S256` |

### 3. 推荐接入方式

建议使用标准 OIDC 客户端库接入，例如：

- Angular：OIDC 客户端库
- React / Vue：支持 Authorization Code + PKCE 的 OIDC 库
- 原生前端：遵循 OIDC 授权码 + PKCE 标准流程

推荐流程如下：

1. 前端跳转到 IAM 授权端点
2. 用户在 IAM 完成登录
3. IAM 回跳到 `redirect_uri`
4. 前端使用 `code` 换取令牌
5. 前端使用 Access Token 调用受保护 API

### 4. 前端接入注意事项

- 不要在浏览器前端保存客户端密钥
- SPA 应使用 `Public` 客户端并启用 PKCE
- `RedirectUris` 必须与前端实际回调地址完全一致
- `PostLogoutRedirectUris` 必须与登出后的实际跳转地址一致
- 如果前端会直接调用 IAM 的跨域接口，需要在 IAM 中配置允许的 `Cors:AllowedOrigins`

## 第三方受保护 API 接入

### 1. API 需要配置的认证参数

受保护 API 需要将 IAM 作为令牌颁发方，并声明允许的 Audience。

关键配置如下：

| 配置项 | 说明 |
|---|---|
| `Authority` | IAM 地址，例如 `https://iam.example.com` |
| `Audiences` | API 接受的资源标识，例如 `MyApi` |
| `RequireHttpsMetadata` | 生产环境建议开启 |
| `ValidateAudience` | 建议为 `true` |

### 2. 接入步骤

1. 在 IAM 中创建或确认目标 API Resource，例如 `MyApi`
2. 将第三方前端客户端与该 API Resource 建立授权关系
3. 在第三方 API 中配置：
   - `Authority = https://iam.example.com`
   - `Audiences = [ "MyApi" ]`
4. 在需要保护的接口上启用授权校验

### 3. Bearer Token 校验重点

API 在验证令牌时，至少需要确认：

- 令牌由当前 IAM 签发
- 令牌未过期
- Audience 与当前 API 对应资源匹配
- 调用方具备目标接口所需权限或作用域

## CORS 与回调配置建议

### 前端调用 IAM API 的场景

如果第三方前端需要直接调用 IAM 的接口，例如：

- `userinfo`
- 授权记录接口
- 用户权限接口

则需要在 IAM 中配置允许的跨域来源：

- `Cors:AllowedOrigins`

例如：

- `https://app.example.com`
- `https://admin.example.com`

### 仅通过浏览器跳转完成登录的场景

如果前端只通过浏览器跳转完成登录，而不直接跨域调用 IAM API，则重点保证以下配置正确即可：

- `RedirectUris`
- `PostLogoutRedirectUris`

---

## 建议的接入顺序

### 前端客户端

1. 在 IAM 创建客户端
2. 配置回调地址与登出回调地址
3. 配置作用域与 API 资源
4. 使用 OIDC Authorization Code + PKCE 接入
5. 如需跨域访问 IAM API，再配置 CORS

### 后端 API

1. 在 IAM 中定义 API Resource
2. 在 API 中配置 `Authority` 与 `Audience`
3. 在接口上启用鉴权
4. 使用前端令牌进行实际调用验证

---

## 常见问题

### 1. 登录后无法回跳前端

通常是以下原因：

- `redirect_uri` 与 IAM 中登记的 `RedirectUris` 不一致
- 前端实际地址与配置地址不一致
- 协议、域名、端口或路径不一致

### 2. API 返回 401

通常需要检查：

- 是否正确附加 Bearer Token
- Token 是否过期
- `Authority` 是否配置为正确的 IAM 地址
- API 是否接受当前 Audience

### 3. API 返回 403

通常表示：

- 当前用户已登录
- 当前令牌有效
- 但缺少目标接口要求的作用域、资源或权限

### 4. 前端跨域调用 IAM 失败

通常需要检查：

- IAM 的 `Cors:AllowedOrigins` 是否包含当前前端来源
- 是否误把回调地址配置成 CORS 白名单，或反过来

回调地址与 CORS 白名单是两个不同概念，需分别配置。
